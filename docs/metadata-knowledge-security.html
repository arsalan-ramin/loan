END-TO-END ACCESS INVARIANT  ·  No agent or user can retrieve content beyond approved identity, entitlement, purpose, source and classification.

Observability returns evidence to governance for recertification, incident response, and source / model change review. Security controls can stop or restrict a route at any stage.

Cross-plane rule: every model, MCP tool, agent handoff, cache lookup, retrieval index, data-lake query and analytics call uses an approved route. Authorization is evaluated before data enters the agent context; state and cached results remain scoped to identity, tenant, purpose and expiry.
01 / Metadata contract | minimum fields for a governed knowledge item

Apply metadata consistently to source records and derived chunks. Keep source-of-truth content in its governed system; the index is a controlled retrieval projection with traceable provenance.

Schema rule: distinguish immutable provenance (where data came from and which version) from mutable authorization (who can access it now). Derive access from the authoritative policy / ACL service where feasible; do not rely on a stale copied permission as the only control.

02 / Knowledge-store lifecycle | source remains authoritative
1 / APPROVE SOURCEOwner, purpose, classification, access path and review evidence are registered.
2 / INGESTAuthenticate connector; validate format, labels, malware / content policy and provenance.
3 / NORMALIZEExtract, chunk and enrich while preserving source IDs, version and ACL lineage.
4 / INDEXPublish to the approved store; apply retention, encryption and access controls.
5 / REFRESH / RETIRESync changes, propagate revocations / deletions, monitor failures and attest freshness.

Knowledge-store design principles

  • Separate authoritative content from derived embeddings, chunks, caches and search indexes.
  • Partition by approved tenancy / security boundary where required; isolate development, test and production.
  • Encrypt in transit and at rest; restrict service identities, operators, backup access and administrative paths.
  • Provide freshness / deletion SLAs, re-index controls, backup recovery and auditable lifecycle events.

Ingestion and content trust

  • Allowlist connectors and source locations; validate types, size, structure and source ownership.
  • Treat ingested text as untrusted data, not instructions; retrieval content cannot grant tools or alter system policy.
  • Quarantine parsing, classification, malware, provenance or ACL-sync exceptions; alert an accountable owner.
  • Reconcile indexed counts and deletions to source manifests; report freshness and failed syncs.
03 / Metadata filtering | authorize before context assembly

Request context

Resolve the human caller, authenticated workload / agent identity, tenant, approved use case, purpose, and delegated permissions. Reject missing or expired identity context.

Policy decision

Evaluate user and agent entitlements together against source ACL, classification, purpose, jurisdiction, tenant boundary, effective dates and current policy.

Constrained retrieval

Pass mandatory authorization predicates to the retrieval / data service before results are returned. Apply the same controls to vector, keyword, cache, reranker and structured-data paths.

Re-check and minimize

Validate returned records and citations, remove disallowed fields, minimize context, and deny rather than broaden access when filters cannot be enforced or verified.

Non-negotiable: post-retrieval filtering alone is not an authorization boundary: unauthorized content may already have reached the application, logs, reranker or model context. Fail closed if policy evaluation, ACL synchronization or tenant scoping is unavailable.

Data-access operating model

  • Business / data owners approve sources, purposes, labels, populations and access conditions.
  • Security / Privacy / Legal review sensitive data handling, residency, retention and vendor / connector paths.
  • Platform owns identity, policy enforcement, logging, secret management and emergency disablement.
  • AI application owners keep agent inventory, tool scopes, evaluations and runbooks current.

Evidence and incident readiness

  • Correlate request, user / workload identity, authorization decision, source references, model / prompt version and tool actions.
  • Do not indiscriminately log raw sensitive content; define redaction, access, retention and evidence integrity.
  • Exercise incident playbooks for data exposure, poisoned / stale source, identity compromise and unsafe action.
  • Test the stop path and confirm it revokes subsequent retrieval / tool access, not only UI availability.
